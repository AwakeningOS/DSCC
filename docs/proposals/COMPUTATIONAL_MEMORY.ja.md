## 1. 発想

サイズも能力も違うAIが同じ記憶基盤へ参加する場合、すべてのAIに同じ文体や高度な分類作業を要求すると、参加するモデルの能力差が記録の使いやすさへ直結してしまう。記録が増えるたびに別の生成LLMへ読み直しと要約を依頼する方式では、その処理にも費用がかかる。

そこで、**原本を保持し、その上に数値計算で更新できる記憶の地図を作る**。内容のハッシュ、共通の埋め込みプロファイル、文字列検索、実行履歴から得られる接続関係、グラフ上の点数伝播を組み合わせる。新しい記録の取り込みや通常検索では、生成LLMによる分類・書き換えを必須にしない。

AIは必要な証拠が集まった段階で、それを解釈し、仮説を立て、次の仕事を考える。高性能な整理エージェントによる要約や意味解析も利用できるが、それらは出典付きの追加資産として扱い、原本の代わりにはしない。

この案で共通化したいのは、各AIの考え方ではなく、**原本の識別、検索用表現の互換性、記録同士の接続、原本へ戻る方法**である。高度な研究用の構造化データと、簡単なメモの両方を受け入れ、それぞれの情報量を保持する。

## 2. 具体的な利用例

あるAIが「同じ層を繰り返したら文章予測が改善した」と書き、別のAIが「重みを共有して追加計算を行うと予測誤差が小さくなった」と書いたとする。共通の変換器で埋め込みを作れば、異なる言い回しでも関連候補として検索できる可能性がある。埋め込みによる意味検索にはSentence-BERTなどの先行研究がある。[S1]

同時に、実行環境は使用したコード、設定、入力、結果の識別子を結び付ける。後から「反復処理はどの条件で有効だったか」と聞かれたら、類似する文章を探すだけでなく、見つかった実験に使われた設定と測定ログも取り出す。

「改善した」と「改善しなかった」が近くに見つかる場合もある。両者は同じ方法を扱っているので、一緒に読む価値がある。検索の近さは関連性を表し、賛否や科学的正しさは別に扱う。

## 3. 現行コードとの関係

確認時点の実装には、署名付き小規模記録、CID、親記録への参照、SQLiteへの永続保存、タイトルと要約の文字列検索がある。記録の種類はラベルとして存在するが、種類ごとの豊かな意味処理は未実装である。根拠は [models.py](../../src/dscc/models.py)、[store.py](../../src/dscc/store.py)、[PROTOCOL.md](../PROTOCOL.md)。

本案はその上に追加する検索・整理層の提案であり、ベクトル検索、グラフ伝播、連合検索が既に動いているという報告ではない。コード、既存CID、署名対象のバイト列、保存形式、公開権限を今回変更しない。

現在のSQLiteは原本のenvelopeと索引用メタデータを同じデータベースに保持している。したがって「索引を消して再構築する」試験で、この既存データベース全体を削除してはいけない。新しい派生索引を別ファイルまたは明確に分離した領域へ置くところから設計する。

## 4. 原本と、作り直せる検索層

| 層 | 保存するもの | 扱い |
|---|---|---|
| 原本 | 研究記録、実験出力、コード、設定、出典 | 署名と内容を検査して保持する |
| 抽出表現 | 原文の区間、JSON Pointer、対象ID、測定条件など | 抽出方法と原本位置を記録する |
| 数値索引 | 埋め込み、語句索引、近傍候補 | 原本から再構築可能にする |
| 接続グラフ | 入出力関係、派生、時間順、類似候補 | 辺の種類と根拠を保持する |
| 取得結果 | 原本の該当箇所、設定、測定値、出典への経路 | 利用するAIへ渡す |

大きなファイルは区間や項目に分けて検索するが、取得結果から元のファイルと位置へ戻れるようにする。文章の区切り方、コードの区切り方、数値配列の扱いは媒体に合ったアダプターへ分ける。モデル重みや大規模配列を文章へ変換して保存することは要求しない。

現行seedには小規模JSONレコードの上限があるため、大規模ファイルへの対応は既存のストレージ拡張と調整する。

## 5. 統一するのは検索用の座標系

同じ索引で直接比較するベクトルは、同じ `embedding_profile_id` に従って作る。プロファイルには、モデルの正確なrevisionまたはdigest、トークナイザー、入力抽出、区切り方、query/document別の前処理、pooling、次元、正規化、数値形式を含める。モデル名だけでは互換性の識別に足りない。

正規化したベクトルを使う場合、ゼロでない埋め込みについて次のように比較する。

```text
v_i = E_profile(chunk_i) / ||E_profile(chunk_i)||
similarity(q, i) = dot(v_q, v_i)
```

`E_profile` は指定プロファイルの埋め込み処理である。正規化済みベクトルの内積はコサイン類似度に一致する。生成による長い要約を毎回作る代わりに、エンコーダーの計算と近傍検索で関連候補を集める。[S1]

世界中のノードに一つのモデルを永久に強制する必要はない。ノードは複数のプロファイルを併設できる。異なるプロファイルのベクトル同士の直接比較や、未校正の類似度の単純合算は行わない。相手が異なる索引を使っている場合は、取得を許可された原本を自ノードの方式で再評価するか、出典付き候補として別の順位統合を行う。

索引変更時には、新旧の索引を並べて検証してから切り替える。原本を書き換える必要はない。異なる実行機器で同じプロファイルを使っても浮動小数点出力の完全一致は仮定せず、埋め込みは原本の身元確認には使わない。

## 6. 接続の種類を分ける

| 接続 | 作り方 | 意味 |
|---|---|---|
| `similar_to` | ベクトル近傍 | 内容の関連候補 |
| `derived_from` | 明示された親記録や変換履歴 | どの資産から作られたか |
| `used_input` / `produced_output` | 実行環境の記録 | 処理が何を使い、何を出したか |
| `same_run` / `next_in_session` | run ID、session ID、局所順序 | 同じ実験や作業の周辺文脈 |
| `supports` / `contradicts` / `supersedes` | 根拠付きの主張・検証記録 | 誰が何を支持・反証・訂正したか |

前半の機械的な接続を整理の土台にする。自然文を理解しなければ作れない意味関係は、別の抽出器やAIが追加できる。ただし、作成者、方法、出典、確認状態を持つ提案として扱う。

`similar_to` から `supports` を自動的に導かない。現行の `parents` は汎用の参照であり、その存在だけから「支持」「同一実験」「訂正」を推定しない。異なるノードの時計だけから確かな全体順序を作らず、明示された依存関係とセッション内の順序を優先する。

近傍索引にはHNSWを候補として使える。HNSWは近いベクトルを探すための既知の索引方式である。[S2] HNSW内部の探索用リンクと、実験来歴のグラフは別々に管理する。

## 7. 読み出しを計算の流れにする

### 取り込み

原本の形式、容量、取得権限、CID、署名を検査して保存する。索引用の区間を抽出し、語句索引と埋め込みを更新する。実行環境が持つ入出力や親子関係を追加し、近傍候補を更新する。解析に失敗した原本も、保持が許可される範囲では原本として残し、索引化できなかった状態を明示する。

この基本経路では、生成LLMによる再作文や分類を必須にしない。エンコーダーの計算時間、メモリ、電力、索引更新費用は別に測る。

### 検索

まず、利用者がアクセスできる資産だけを対象に、文字列検索とベクトル検索から候補を集める。版番号、コード名、単位、数値、明示された測定条件は、意味類似度だけに任せず条件照合にも使う。異なるスコア尺度の統合方法は検証対象とし、初期の係数を実証済み最適値として扱わない。

その候補を起点として、関連グラフへ点数を伝える。Personalized PageRank型の反復は次の形で表せる。これは本案の数理的な出発点であり、DSCCで測定した結果ではない。知識グラフとPersonalized PageRankによる記憶検索にはHippoRAGという先行研究がある。[S3]

```text
p_next = (1 - alpha) * q + alpha * P^T * p
```

`q` は検索候補から作る非負・総和1の開始分布、`P` は取得権限のあるグラフの非負の行確率行列、`0 < alpha < 1` は伝播の強さである。行き先のない点は `q` へ戻す規則を定義する。停止は残差と反復予算で決める。`alpha`、辺の重み、近傍数は未決定の調整対象とする。

得られる点数は「読むと役立ちそうか」であり、「正しい確率」ではない。反証への辺も、読むべき関連情報として辿れるようにし、負の遷移確率にはしない。高次数のノードが無条件に支配しないよう、辺の種類ごとの正規化、重複由来の寄与制限、プロジェクト範囲の絞り込みを検討する。

最後に、選んだ実験に必要な入力・測定条件・結果・訂正記録を追加取得し、原本の位置と経路を付けてAIへ渡す。文脈予算を超える場合は、結果の一部や依存関係を省いたことを明示する。見つからなかった情報は欠落として返す。

### 検索結果の説明

各候補には、原本CID、原本内の位置、使用した索引プロファイル、文字列一致や類似度による取得理由、辿った辺、参照できなかった依存先を含める。AIの最終回答がどの記録を使ったかを後から確認できる形にする。

## 8. 重複と矛盾を、知識の損失なしに扱う

現行seedのCIDは署名を含むenvelope全体に付いている。同じ本文でも別の鍵が署名すれば別CIDになる。従って、新しい索引で本文や区間のdigestを使って重複候補をまとめる場合も、元の署名とCIDはすべて保持する。[PROTOCOL.md](../PROTOCOL.md)

バイト列が一致する重複と、意味が似ている記録は区別する。近いベクトルは削除や同一視の根拠にせず、検索候補をまとめて表示するために使う。同じ元実験を十体のAIが言い換えても、十回の独立再現として数えない。一方、実際に独立して再実行した記録は、文章が同じでも別の実行として残す。

矛盾した結果は両方を原本へ辿れるようにする。数値や条件の明確な照合は計算で扱えるが、任意の自然文に含まれる科学的矛盾を内積だけで判定できるとは想定しない。訂正は出典付きの新しい記録として追加する。

## 9. 分散ネットワークへ広げるとき

各ノードが保持する索引は、そのノードが参照を許可された原本から作る局所的な見取り図とする。全参加者が一つの巨大グラフや唯一の分類体系へ合意する必要はない。

将来の連合検索では、相手ノードから原本CID、原本位置、プロファイル、関連候補を受け取り、必要な原本を取得して検証する。完全な原本が取得できない結果は候補のままである。P2Pの所在探索と、内容の意味検索は別の機能として実装する。

ベクトルと索引は匿名化データとして扱わない。非公開原本から作った埋め込みも同じ共有範囲に従う。権限確認は最終表示時だけでなく、候補生成とグラフ伝播の前に適用する。他ノードのベクトル、関連リンク、件数報告を無条件に信用せず、受入容量や検査を設ける。参加数や引用数をそのまま真理の投票にしない。

一台のPCでも局所索引を利用でき、ノードが増えたら参照可能な資産が増える。HNSWやPageRankを採用しただけで、分散通信、アクセス制御、改ざん耐性、ネットワーク分断まで解決したとは扱わない。

## 10. 実装へ進むときの引き継ぎ

この提案はT007の索引再構築と接続するが、T007の作業範囲を黙って増やしたり完了扱いにしたりしない。実装前に [AGENTS.md](../../AGENTS.md) を読み、関連Issueで担当範囲を調整する。

最初に、原本を保持したまま別領域に語句索引・埋め込み索引・接続グラフを作れるインターフェースを設計する。次に、候補検索、来歴の追加取得、関連グラフ探索、原本への位置参照を一つの取得経路へ結ぶ。将来の連合検索や高度な整理エージェントを載せられる契約を保つ。構成を弱めて比較しやすくすることは設計目標にしない。

実装時の受入観点は以下とする。数値目標は対象データと計算機を決めてから設定する。

- 同一内容の言い換え、専門用語、コード識別子、異なる言語を含む記録で、必要な原本に到達できるか。
- 正反対の結論、異なる測定条件、後日の訂正が混在しても、検索が勝手に一つの結論へ統合しないか。
- 同じ出典の複製と独立再実行を混同せず、根拠となる入力・条件・出力を辿れるか。
- 新しい索引だけを削除して原本から再構築できるか。旧CID、署名、既存プロトコルを保持できるか。
- 索引プロファイルを更新・併設しても互換性のないベクトルを混ぜないか。
- アクセス外の記録、悪意ある索引、検索結果内の命令文が権限や処理方針を変更しないか。
- 取り込み時間、検索時間の中央値と遅い側、RAM、索引サイズ、エンコーダー費用、生成LLM呼び出し数を測る。検索品質はRecall@k、根拠回収率、条件の取り違え、実際の作業継続の成否で確認する。

比較は各方式に適した設定で性能と費用の関係を評価する。特定モデルの能力不足を索引の欠陥と混同しないよう、検索単体の根拠回収と、複数の読み手モデルによる利用結果を分けて測る。採用する検索器、エンコーダー、辺の規則は公開した評価で更新可能にする。

## 11. 先行研究と本提案の区別

文献の存在と本節の要約は、2026-09-17に一次資料の要旨で確認した。性能の追試、実装コードの監査、DSCCへの統合は行っていない。以下の手法をDSCCへ組み合わせる部分は、本提案の設計仮説である。

- **[S1] Nils Reimers and Iryna Gurevych, Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks (2019).** 文を埋め込みへ変換し、コサイン類似度で比較する先行研究。DSCC全体の実証ではない。https://arxiv.org/abs/1908.10084
- **[S2] Yu. A. Malkov and D. A. Yashunin, Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs (2016; revised 2018).** HNSWによる近似近傍探索の先行研究。索引の探索用リンクを科学的な来歴と同一視しない。https://arxiv.org/abs/1603.09320
- **[S3] Bernal Jiménez Gutiérrez et al., HippoRAG: Neurobiologically Inspired Long-Term Memory for Large Language Models (NeurIPS 2024).** LLM、知識グラフ、Personalized PageRankを組み合わせる記憶検索。システム全体が生成LLM不要という根拠ではなく、グラフ検索の先行研究として参照する。https://arxiv.org/abs/2405.14831
- **[S4] Yilin Xiao et al., Zero-Mem: Zero-Token Memory Operations for LLM Agents (2026, preprint).** 原本の履歴を保持し、entity-context graphと時間的な構造を用いて、記憶操作時の生成LLM呼び出しを省く提案。エンコーダー費用は別計上される。要旨にはコードと実装詳細を査読後に公開する予定とあるため、この資料から既に再利用可能な実装があるとは主張しない。会話記憶での報告を、分散科学資産の性能証拠として流用しない。https://arxiv.org/abs/2607.29377

Zero-Memは「生成LLMによる中間記憶の作文を必須にしない」という方向の先行研究になる。[S4] 本案はその発想を参照しつつ、実験の来歴、複数モデル、分散取得、既存DSCCの不変記録と結び付ける。ベクトル検索やグラフ探索そのものの新規発明を主張するものではない。

## 12. 今回の到達点

保存したのは、**原本を失わず、数値と接続関係を使って、モデルの違いを越えて経験へ辿り着く**という設計案である。AIによる高度な解釈を残しつつ、日常的な整理作業の多くを生成ではなく索引計算へ任せることを目指す。

この文書には新規の実装、性能測定、テスト成功報告を含めていない。実装へ進む際は別の作業ブランチとレビューで既存システムへ接続する。
