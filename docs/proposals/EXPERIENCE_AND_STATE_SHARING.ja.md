## 1. 目的

DSCCに蓄積するのは、研究の結論に加えて、そこに至る試行錯誤と、経験を処理したAIが形成した利用可能な状態である。あるAIが失敗・修正・成功を経験した後、次のAIが同じ地点から研究を続けたり、別の関連問題でその経験を利用したりできる研究所を目指す。

そのために、原本を読み直して理解する経路と、対応するモデルへ内部表現を渡す経路を併設する。全AIへ一つの内部表現を強制せず、来歴・形式・変換器・評価の共通契約によって異なる参加者を接続する。クローズAIは外部記録を通じて参加でき、内部状態の正式な入出力手段を持つモデルは潜在転送にも参加できる。

本案は既存T010（探索経路の再利用）、T012（研究状態の引き継ぎ）、LEC（潜在経験カプセル）、OMC（モデルと計算資源）を接続する。実装の都合で本命設計を弱く固定せず、完成形の自由度を残して個別の実装・検証課題へ分ける。

## 2. 三つの共有単位と変換器

| 単位 | 保存するもの | 用途 |
|---|---|---|
| 経験グラフ | 原本、操作、観測、仮説、失敗、分岐、証拠、当時の入力への参照 | 他のAIや人間が経緯を調べ直し、研究を継続・再解釈する |
| 作業状態スナップショット | 特定の入力接頭辞に対応するKV等の状態、モデル・実行条件、再開位置 | 同じ作業を別プロセス・別モデルへ引き継ぐ |
| 潜在経験カプセル | 経験の効果を保持する目的で抽出・圧縮した表現と評価 | 未見の関連課題へ過去の経験を持ち込む |
| 変換器・注入器 | 入出力形式、方向、コード・重み、校正条件、評価、適用範囲 | 状態を相手が利用できる形へ変換し、その変換自体を改良する |

KVキャッシュは過去トークンのKeyとValueを保持する推論用データであり、エージェントの実行状態全体とは区別する。エンベディング（検索用の数値表現）は、版管理された派生索引として扱う。

**同じ文脈の継続、異なる資料からの情報追加、未見課題への経験転移を別の評価対象にする。** 前者の成功を、そのまま後者の実証にしない。対応する先行研究と範囲は[S05–S09](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s05)に整理した。

## 5. 実行環境から経験を記録する

### 5.1 事実と解釈の出所

ハーネス（モデルやツールを動かす実行管理部分）が、呼び出しID、実引数、開始・終了、出力、終了コード、変更前後のファイル、生成物を捕捉する。AIの事後報告だけで実行ログを再構成しない。

由来は、実行環境の観測、当時の明示的な発言、後日の抽出・解釈、説明用の合成例、不明に分ける。選ばれなかった候補は当時記録されていたものだけを残す。後から生成した仮説を、当時検討済みだったものとして埋めない。隠れた思考の取り出しを共有の必須条件にはしない。

次は役割を示す草案であり、現行APIへ投入できるスキーマではない。

```text
Episode / Run
  producer・schema_revision・run_id・trajectory_id
  goal_ref・environment_snapshot_ref・branch_refs

Decision / Action / Observation
  event_id・attempt_id・local_sequence・branch_id
  visible_context_ref                  当時渡された入力
  explicit_hypothesis_ref               明示された仮説、なければ不明
  declared_candidates・selected_action  記録された選択肢と選択
  tool_call_ref・observation_ref         操作原本と結果原本
  state_before_ref・state_after_ref     状態と差分の検査用
  evidence_refs・origin・capture_gaps   根拠、由来、欠落

Assessment
  assessed_event_ref・evaluator_ref・metric_definition
  measured_outcome・interpretation・counterevidence_refs
```

成功・失敗・報酬には、指標、評価者、対象、時点、比較条件を付ける。終了コード0、課題の成功、仮説の支持は別の情報である。測定値と、その値をどう解釈したかを分離する。

### 5.2 当時の入力を復元する

原本が500行あっても、AIへ渡したのが最後の30行だけなら、その判断の入力は30行の方である。実際のメッセージ、取得部分、切り詰め、画像等の参照、ツール定義、文脈圧縮後の入力を記録する。取得可能ならトークンIDもトークナイザーの版と組にする。観測できないサービス内部の状態は欠落として残す。

ATIFのコピー文脈・文脈管理・サブエージェント参照と対応付ける。実行ID、文書ID、試行ID、ツール呼び出しIDを区別し、同じ履歴のコピーを独立した経験として水増ししない。[S01](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s01)

出来事の発生時刻、受信・記録時刻、実行内の順序を分ける。分散ノードの時計だけから唯一の全体順序を作らず、明示的な依存関係とスナップショットを使う。過去時点の取得に、その後判明した反証や更新済み探索統計を混ぜない。これはTrellisの時間遡及を参考にしたDSCC側の設計課題である。[S03](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s03)

### 5.3 グラフの辺を区別する

入力・出力・分岐・実行順は、収集器が観測した実行関係として扱う。`tests`、`supports`、`contradicts`、`supersedes`や原因についての主張は、主張者・根拠・確認状態を持つ別資産として追加する。順序だけから原因を確定しない。

実行依存や不変成果物の親参照にはDAG（循環のない有向グラフ）が適する。一方、意味類似・相互参照・競合する解釈まで含む全グラフを一つのDAGへ押し込まない。操作の反復は各回を別イベントにし、訂正は新しい記録から以前の記録へ接続する。

## 6. 原本・検索・表示を分離する

| 層 | 保持する情報 | 更新方法 |
|---|---|---|
| 原本 | 許可されたログ、コード、資料、画像、計測値 | 不変の版として保持 |
| 実行イベント | 操作、観測、差分、入力文脈、分岐 | 原本位置と収集器の版を保持 |
| 解釈・経験 | 仮説、教訓、失敗理由、異分野の対応付け | 別解釈や反証を追加 |
| 検索索引 | 語句、埋め込み、構造特徴、利用統計 | 原本と抽出結果から再構築 |
| 表示 | 要約、選択した経路、用途別説明 | 出典付き派生物として再作成 |
| 潜在表現 | 生KV、変換KV、圧縮カプセル | 生成条件・互換性・評価を版管理 |

語句・意味・探索構造から独立に候補を取得し、必要な枝と証拠を広げる。T010に従い、構造検索を意味検索の上位候補だけへ限定しない。小型の判定モデルを選別・再順位付けに利用できるが、候補数を実験しやすさのための固定制約にはしない。

取得単位は「似た失敗経路」「成功した枝と兄弟候補」「判断時の入力」「後から反証された仮説」などとする。応答には取得範囲、欠落、ページ継続位置、原本位置を含める。部分取得を全履歴と表示しない。同じ出典を複製・再要約した記録は、独立した確認の件数へ加算しない。

## 7. 作業状態の互換性と再開契約

モデル名だけで互換性を判定せず、次の情報を組にする。以下は設計候補であり、必須フィールドの確定は後続ADRで行う。

| 項目 | 記録する情報 |
|---|---|
| モデルの同一性 | 重み・設定・追加アダプターのdigest、正確なrevision、量子化、トークナイザーとチャットテンプレート |
| キャッシュ形式 | 層・ヘッド対応、テンソル形状、数値型、量子化係数、配置、RoPEの設定と適用状態、位置ID、マスク、窓の範囲 |
| 文脈との対応 | 元の入力・トークン列への参照、接頭辞長、処理済み範囲、未処理トークン、切り詰め・圧縮履歴 |
| 変換器 | 方向、コードと重み、入力・出力形式、校正データ、対応する注入方式、受信側KVが必要か |
| 実行再開 | デコード位置、必要な直前トークン／出力、サンプラーと乱数状態、停止条件、制約付き生成の状態 |
| エージェント環境 | 作業ツリー・ファイル版、ツール版、未完了ジョブ、外部状態への参照、副作用の処理状態 |
| 評価と権限 | 対象課題・文脈長での品質、再現性の区分、アクセス範囲、生成者・変換来歴 |

KVを戻せても、書き込み途中のファイルや外部ツールの状態は戻らない。ログ再生、環境復元、モデルの継続、研究上の再解釈は区別して報告する。副作用を伴う操作を再開時に自動再実行せず、未完了・完了不明を扱う仕組みをジョブ層へ接続する。

API経由でのみ使えるモデルには、正式なキャッシュ入出力手段がある場合だけ内部転送を接続する。利用できない場合も、経験グラフとT012から参加できる。GPT→Claude等は将来の接続可能性として保持し、モデル名から入出力機能や互換性を推定しない。

## 8. 直接変換・融合・圧縮・共通空間を併設する

直接変換は、受信側の同じ接頭辞処理を省く経路。融合は、受信側が既に持つ文脈へ他者の情報を加える経路。共通潜在空間は、複数モデルを各々の変換器で接続する経路。圧縮は、送る表現と保存する表現を小さくする経路として管理する。[S05–S11](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s05)

変換器は有向の接続として登録する。A→Bで良好でもB→Aを自動的に承認しない。A→B→Cの合成結果も、A→Cと同じ品質とは仮定しない。直接変換、複数段変換、再読み込みを選択肢に残し、原本または検証済み状態から復帰できるようにする。

RoPEの回転を外しても、KVに含まれる内容が元の接頭辞や文脈から独立するわけではない。異なる履歴で作ったキャッシュ断片を単純連結しただけで、有効な文脈になるとは扱わない。圧縮と変換の順番、複数カプセルの注入順、位置合わせ、モデル本体の変更との関係を評価する。

潜在経験カプセルは、元経験の再構成誤差に加え、未知の関連課題での判断改善を目的にする。表現の数値が近いことと、実行結果が保たれることは別なので、回答だけでなく次の実験選択や失敗回避も測る。経験が誤っていた場合や、新しい条件に合わなくなった場合の負の転移も残す。

## 9. 世界分散での費用と経路選択

選択する経路ごとに、取得、圧縮、シリアライズ、通信、受信側への配置、変換、注入、準備、追加のプリフィルを測る。並行可能な処理は二重加算せず、利用者が待つクリティカルパスも記録する。変換器を作る校正費用と、リクエストごとの費用は分け、再利用回数に対する償却を考える。

```text
概算の逐次費用:
  T_handoff = T_capture + T_encode + T_transfer
              + T_load + T_map + T_inject + T_remaining_prefill

比較先:
  T_restart = T_fetch_original + T_model_ready + T_receiver_prefill
```

送信側KVが既にある切り替え場面と、KVを作るために送信側を新しく動かす場面も分ける。S05のGPU上の変換時間を、そのままWAN上の切り替え時間にはしない。S06の変換器小型化を、キャッシュの通信量削減とも混同しない。[S05](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s05)、[S06](experience-sharing/SOURCES_AND_EVIDENCE.ja.md#s06)

説明用の仮定として、バッチ1、64層、KVヘッド8、ヘッド次元128、32768トークン、各要素2バイトなら、未圧縮KVは次の容量になる。

```text
2(KとV) × 64 × 8 × 128 × 32768 × 2 = 8 GiB
8 GiB × 8 / (1,000,000,000 bit/s) ≈ 68.7秒
```

これは実モデルや回線の実測ではなく、直列送信の概算である。通信・配置を含む費用次第で、同一拠点の直接KV変換、遠隔への圧縮表現、原本からの再構成を使い分ける。

ルーター（使用モデルや経路を選ぶ処理）は、自己申告の確信度だけに依存させない。課題種別、実測した転送品質、利用可能資源、通信量、遅延、予算から選ぶ。8B→14B→32B→70Bという段階的昇格は一つの候補であり、必要なモデルへの直接転送や、小さいモデルへ戻す経路も評価する。

## 10. 現在のDSCCへの接続

現行実装の出発点は[研究継承契約](../RESEARCH_HANDOFF.md)と[プロトコル](../PROTOCOL.md)。T012の九つの研究プロファイル、CID／JSON Pointerによる出典、明示された研究状態からの全祖先取得を使える。T010の検索・対応付け、実モデルの状態転送は別の実装課題として残る。

追加するプロファイルは、既存の署名済みバイト列、CID、最上位の種類を維持した版付き拡張として設計する。現在のT012は未知のトップレベル項目を受け付けず、`content.extensions`に置いた任意参照も自動的な依存関係にはしない。新しい軌跡・状態・変換器の意味を、単に拡張欄へ書いただけで実装済みにしない。

ATIFのコスト等には浮動小数点や外部媒体の参照が含まれ得る。制限JSONの現行seedへ機械的に投入せず、元ファイルのバイト列を許可範囲で保持し、変換したメタデータに原本と変換規則を付ける。十進文字列・単位への変換、JSON位置参照、大容量バイナリの範囲参照を明示し、元値を丸めて置き換えない。

現在の直接親32件、記録約1 MiB、bundle 256件・8 MiBという上限に対して、長い軌跡は分割マニフェスト、段階的取得、継続参照を設計する。大容量ブロックの保存は既にあるが、seed bundleはそのバイト列を運ばない。T005／T011の転送・修復と接続し、メタデータだけ届いた状態を完全な再開状態と表示しない。

`catalog.sqlite3`は原本の署名済み記録も保持する。新しい派生索引は別領域に置き、索引再構築の際に原本を削除しない。変換器の重みとコードもOMC・Tool等への版付き参照で管理し、生成されたKVやカプセルの来歴へつなぐ。

## 12. 実装の分担と受入条件

まず文献・仕様・既存実装から既知の答えを整理し、DSCCで追加して確かめる問いを記録する。作業順は世界規模ネットワークの完成待ちに固定せず、ローカルで進められる経路と、実ハードウェアが必要な経路を並行させる。

| 作業経路 | 成果物 | 受入で確認すること |
|---|---|---|
| A: 軌跡取り込み / T007・T010 | 版別ATIF変換器、実行境界の収集器、原本と欠落の記録 | 操作・出力・順序・出典が保持され、未知項目を黙って消さない |
| B: 経験の検索 / T010・T012 | 独立した意味・構造検索、枝の取得、対応付け、研究状態への参照 | 別クライアントから原本へ戻れ、部分取得と全体を区別できる |
| C: 状態と変換器 / T007・T011・LEC | 状態マニフェスト、互換性検査、変換器登録、復元手順 | モデル・入力・形式の不一致を検出し、実行の権限と分離する |
| D: 実モデル転送 / T003・T006・T011 | 直接変換、融合、圧縮、再プリフィルの実行アダプター | 実機の品質・時間・容量・再開位置を測り、未検証の組合せを明示する |
| E: 経験転移 / LEC・T010・T012 | 未見課題の評価集合、負の転移検査、複数カプセル評価 | 情報再現と判断改善を分け、出典系列・時間による漏れを防ぐ |
| F: 世界分散 / T001・T005・T009・T011 | 分割転送、再送・修復、権限・予算、敵対条件の試験 | 実回線の費用と中断復旧、アクセス制御、偽の記録への耐性を示す |

固定の小型モデルや短い文脈を製品上限にせず、入手可能な計算資源で確認した適用範囲として記録する。共通契約の変更はADRと互換性試験を先に用意する。別担当の評価を入れられるよう、入力・実行・出力・費用の証拠を残す。

## 13. 評価設計

ソフトウェア契約、モデルの継続品質、経験の転移効果を別々に評価する。契約テストが通ったことを、実際のAIの研究能力が改善した証拠にはしない。

同じ課題について、原本を十分に読む方式、出典付き構造化記録、経験グラフからの取得、同一モデルの状態再利用、モデル間変換、圧縮カプセル、グラフと潜在表現の併用を比較候補にする。各方式を自然な強い構成で作り込み、本命から要素を除く比較は後から用意する。

測る項目は、出典保持、判断時点の情報漏れ、研究の再開成功、課題の絶対成績、相対保持率、既知失敗の回避、試行数、負の転移、探索多様性、初回出力までの遅延、全作業時間、通信量、RAM／VRAM、モデル呼び出し回数、校正費用である。モデル・変換器・入力・評価器の版を固定した結果と、更新後の結果を分ける。

校正・検索器調整・最終評価を分け、同じ原本の言い換えが最終評価へ入らないようにする。当時の入力だけを渡す時点制約を用い、未来のテスト結果や正解が混ざっていないことを検査する。可能な範囲で反復と不確実性を記録し、平均だけでなく課題別の失敗を示す。

## 14. DSCC自身の開発を最初の経験にする

PR #19には、研究継承機能の追加、サンプル配置による既存形式テストの失敗、専用フォルダーへの修正、追加検査、テスト成功、マージという実際の経路がある。[検証記録](https://github.com/AwakeningOS/DSCC/pull/19#issuecomment-5810290598)は、当時のCIで157件が通過したことと、実モデルの研究継続実証は残っていることを区別している。

この例では、コミット、差分、CI結果、コメントから復元できる部分だけを経験として取り込む。当時明示されなかった候補や内的判断を作り足さず、復元可能範囲を表示する。その後の開発では収集器を接続し、操作時点から原本と入力を残す。次のAIが同種の問題を直す際、教訓だけでなく失敗した入力と修正差分へ戻れる状態を受入の一例にする。

## 15. 条件が整えば広がる可能性

実際の転移効果が確かめられれば、長期の研究記憶を検索して読む経路に加え、適合する潜在経験を現在の作業へ取り込める。成功経路だけでなく、使えなかった仮説や失敗条件を共有することで、次の参加者が同じ誤りを避け、新しい枝へ進む可能性がある。

検証済みの変換器や注入器が蓄積すれば、モデル交代のたびの再調整費用を参加者間で再利用できる。共通潜在空間を複数モデルが使う構成、専門AIの経験を汎用AIへ提供する構成、軽い処理を小型モデルが進め必要な場面だけ大きなモデルへ渡す構成を研究できる。いずれも対象モデル・課題での評価を伴う条件付きの可能性として扱う。

さらに、許可された経験から教師あり学習用の軌跡、比較可能な兄弟候補、評価付きの試行集合を生成し、OMCでのモデル改良へつなぐ経路もある。学習に使う際は元の出典・評価・選別履歴を残し、コピーされた文脈を新しい試行として数えない。改良したAIが再び研究へ参加し、その成果も同じ経験基盤へ返す循環を最終目標に接続する。
