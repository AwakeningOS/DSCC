## 1. 何を作るのか

異なる人やAIがたどった「状況 → 試したこと → 起きたこと → 考え直したこと → 次の試行」を残し、別の分野にある似た探索経路を検索する。GPU推論の高速化、モデル設計、日常の学習、対人関係の経験を、単に分野別の棚へ分類するのでなく、行き詰まりや判断の変化を含む地図として参照できるようにする。

例えば、演算を速くしても待ち時間が減らず転送を測り直した経験と、勉強時間を増やしても定着せず復習の間隔を調べ直した経験は、対象こそ異なるが「増やす場所を変える前に制約を調べ直した」という観点で比較できる。これは説明用の仮例であり、両者が同じ原因で起きたという証拠ではない。

利用者が「今の行き詰まりと似た経路を、他分野から探して」と依頼すると、対応する経験、対応付けた部分、違う条件、元の証拠、次に確認すべき問いが返る。結果から実際の記録へ戻れることを完成条件にする。

地図は一つの普遍法則や人格を決める装置ではない。複数の見方を持つ局所地図と、それらを結ぶ比較可能な橋である。同じ経験は複数の型に属してよく、型そのものも後の経験で改訂できる。

## 2. 構成と責任

| 層 | 持つもの | 主な処理 |
|---|---|---|
| 原本 | ログ、コード、メモ、観測、出典 | 既存DSCCの保存・署名・CID検査 |
| 探索エピソード | 目的、条件、行動、期待、観測、見直し、未完了の枝 | 実行イベントの変換、出典付き抽出 |
| 数値索引 | 話題・目的・行動の埋め込み、構造の特徴量 | 内積、近傍探索、疎ベクトル演算 |
| 対応付け | 二つの経路のどの部分が似ているか | 型付きグラフ照合、条件差の抽出 |
| 転用記録 | 類推を実際に試した結果 | 試行へのリンク、評価者の報告 |
| 探索の型 | 複数経路に共通する部分構造 | 出典付き抽象化、反例と適用条件の追加 |
| 表示・取得 | 原本、経路、型の三段階の地図 | 根拠と欠落を含む読み出し |

保存形式、索引、表示を分離する。二次元の配置やクラスタ名は画面の見取り図であり、科学的な距離・因果・価値判断にはしない。遠い分野を無理に近づけることより、どの関係が対応したのかを示す。

## 3. 現在のDSCCへどう載せるか

既存の`schema`、CID、署名対象バイト列、14種類の`kind`は変更しない。提案中の内部プロファイル`dscc.atlas/0.1-draft`を`data.atlas`に入れる。`Episode`と`Motif`は既存`MemoryCapsule`、`Bridge`と`TransferAssessment`は既存`EvidenceLink`で包む。試験用のJSON Schemaは[atlas.schema.json](exploration-atlas/atlas.schema.json)に置き、本体のvalidatorへはまだ組み込まない。

外部参照は`CID + JSON Pointer`で保持する。Pointerは取得したenvelopeのルートを起点とし、例えば`/body/data/events/0`を指す。部分文字列や大容量バイナリの範囲参照は今後のアダプター拡張にする。元ファイルを要約へ置き換えない。

新しいエピソードの外部CIDは`parents`からたどれるようにする。現在のseedは直接親32件、記録1 MiB、bundle 256件・8 MiBの上限を持つ。大きな探索は順序と分岐を保った複数のエピソードに分割し、継続参照を残す。上限を超える完全な履歴配布はストレージ／transport拡張との調整事項であり、欠落を黙って切り捨てない。

新しい索引は`atlas-index.sqlite3`などの別領域に置く。現在の`catalog.sqlite3`は原本も保持しているため、索引の再構築試験で削除してはいけない。索引の破損やアルゴリズムの交換が、原本の破損にならない構造を守る。

## 4. エピソードの共通部分

共通化するのは文体や成功の定義ではなく、記録の役割と接続方法である。本文は各分野の表現を保持する。記録が疎でも受け入れ、不明項目を推測で埋めない。

| 項目 | 意味 |
|---|---|
| `goal` / `conditions` | その探索で目指したことと制約。分野を越えて同じ尺度へ変換しない |
| `nodes` | `state, goal, constraint, proposal, action, expectation, observation, revision, question`の役割付き記録 |
| `stage` | `proposed, performed, stopped, unknown, not_applicable`。未実行の案を実行済みにしない |
| `origin` | `logged, self_report, model_extracted, synthetic, unknown`。由来は正しさの点数ではない |
| `sources` | 各ノード・接続の出典と原本内位置 |
| `links` | 向きと種類を持つ接続。`precedes, motivates, expects, produces, revises, branches_to, uses`を初期語彙にする |
| `open_questions` | その時点で残った問い。未探索の全空間を表すものではない |
| `extractor` | 抽出器ID、revision、抽出方式。人手の場合も出典を記録 |
| `extensions` | 名前空間付きの分野固有データ。未知の拡張は保存しても実行しない |

`precedes`は時間／手続き上の前後を意味し、原因を証明しない。`produces`も、実行環境が記録した出力と、本人がそう解釈した結果を`origin`で分ける。ノードの原文、抽象的な役割、後から付けた解釈は同一ではない。

同じ操作の反復は一つのノードの自己循環に縮めず、各回を別ノードとして残す。`precedes`だけは局所的なDAGを要求する。別種の関係や別エピソードへの意味リンクは循環してよい。世界中の時計を比較して唯一の全体時間順を作らない。

数値は元ログに残し、メタデータに出すときは十進文字列と単位を持たせる。改善／悪化は対象指標と比較条件を定めた派生情報であり、恋愛、速度、正答率などを一つの成功数値へ足し合わせない。

## 5. 探索履歴の取り込み

実行環境から得られるコマンド、設定、開始・終了、観測値はハーネスのイベントから取り込む。自由文だけの経験は原本として受け入れ、任意の抽出器が出典付きの構造を追加する。自然文から目的や因果を取り出す処理には言語理解が必要であり、単純計算だけで意味が生まれるとはしない。

抽出器が動かなくても、原本の文字列検索は続けられる。抽出不能な箇所は`unknown`または未索引として返す。別の抽出器が異なる読み方をした場合は別エピソードを作り、同じ原本への参照で結び付ける。

取り込み結果は`ready / partial / failed`と欠落理由を返す。中断後は原本CIDと抽出器revisionをキーに再開できる。同じジョブの再送を新しい独立経験として水増ししない。

新規・変更のあった原本だけを再処理し、索引世代を完成させてから切り替える。検索のたびに全履歴を生成LLMへ読ませる処理は必須にしない。一方、良い抽出器や高度な再評価器を追加する自由度は保持する。

## 6. 分野名と探索構造を別に数値化する

話題の埋め込みと、目的・試した操作の埋め込みを分けて保持する。さらに、ノードの役割と接続の向き・種類から、関係構造の疎な特徴量を計算する。三者は異なる検索経路として利用する。

構造特徴には、役割／接続の頻度、短い型付き経路、方向付きWeisfeiler–Lehman（WL）型の近傍集約を候補とする。WLは先行研究[S3]を応用した派生案であり、完全なグラフ同型判定でも普遍的な意味理解でもない。計算仕様は[IMPLEMENTATION.md](exploration-atlas/IMPLEMENTATION.md)に定義する。

役割だけを見ると、異なる内容の単純な「行動→観測」がすべて似てしまう。そのため、粗い構造一致だけで類推を確定しない。具体的な操作、期待と観測の関係、条件差を後段で比較する。関係を持たない袋状の文章検索だけにも戻さない。

埋め込みと構造特徴にはそれぞれプロファイルIDを付ける。モデルrevision、前処理、正規化、語彙、WL反復数、ハッシュ方式、数値型を固定する。同じ名前の異なる座標系は混ぜない。複数プロファイルの併設と再索引を認める。

## 7. 異分野検索の経路

最初に閲覧権限で対象を限定し、文字列、話題、目的・操作、構造の各索引から独立に候補を得る。**文章検索の上位候補だけを構造比較する方式にはしない。** それでは話題の遠い経験が候補に入らないためである。

候補を順位統合した後、型付きの小部分グラフを対応付ける。対応ノード、保存された関係、対応しない部分、条件の違いを返す。大きいグラフ全体の最適照合を毎回解く代わりに、索引で候補を絞り、探索予算内で複数の対応仮説を保持する。

最後に元ログ、設定、訂正、未完了の枝などを必要な範囲で追加取得する。現在の課題で「次に調べられること」を提案できるが、その実行権限や計算予算は既存のジョブ承認を通す。

検索モードは`topic`（近い対象）、`analogy`（似た探索構造）、`transfer`（転用の報告がある橋）を設ける。analogiesを評価済み技術として扱わず、利用者が探索目的を選べるようにする。

## 8. 類推の橋と、実際に試した記録

`Bridge`は二つのエピソードの対応付けである。ノード対応、関係対応、共通部分、合わない条件、次に確かめる問い、作成方式を記録する。初期状態は常に候補であり、類似度を成功確率や科学的確信度へ読み替えない。

実際に転用したら、別の`TransferAssessment`を作る。どのBridgeを参考にし、どの試行を行い、何を根拠に`helpful / not_helpful / inconclusive / not_applicable`と判断したかを保存する。本人の経験報告と独立した再実行は別である。複数評価が矛盾しても上書きしない。

一度役立った橋を、あらゆる条件で有効な法則に昇格させない。検索では試行対象の条件と評価方法を表示する。同じ原本を言い換えた十件を十回の独立検証として数えず、独立性が不明なら不明と返す。

## 9. 探索の型を育てる

複数の経路の共通部分は`Motif`として保存できる。支持するエピソード、各エピソードとの具体的な対応、適用条件、反例、残された違いを保持する。型は一つの排他的な分類体系にしない。

最初は反復して出現する関係の小部分構造を候補にし、人間やAIが意味付けを追加できる。名前だけが立派な「万能法則」にならないよう、元の探索へ戻れる対応表を必須にする。抽象化をさらに組み合わせる拡張は認めるが、出典のない自己引用ループを支持数へ加算しない。

抽象化から次の探索部品を作るという方向にはDreamCoder[S6]がある。ただし、プログラム合成での実証を、この地図が全分野で転用に成功した証拠として扱わない。

## 10. 画面で見せること

個別表示では、案、実行、観測、見直し、未実行の枝を区別し、クリックすると元のログやメモを開ける。複数経路表示では、似た部分を線で結び、比較条件と未対応部分を並べる。俯瞰表示では、型と経験群をまとめ、倍率に応じて詳しい経路を読む。

色や配置だけに意味を任せず、候補・本人報告・実行記録・訂正・参照不可をラベルでも示す。地図の二次元位置は表示用であり、距離そのものを推論の根拠にしない。図から同じ内容の一覧・JSONへ移れるようにする。

「未探索」は、取得できた記録の中に試行結果がないという意味に限定する。地図にないことから、世界中の誰も試していないとは判断しない。中断された経験や結論が出ていない経験も残す。

## 11. 分散と個人の経験

各ノードは参照許可された資産の局所地図を持つ。連合検索では原本CID、位置、プロファイル、対応案を交換し、取得側で原本を確認する。P2Pへ全世界の一枚のグラフを同期する必要はない。

私的な経験の索引や埋め込みも私的情報として扱う。恋愛や人間関係では、本人の見方を相手の心理的事実へ変換せず、相手の個人情報や会話を無断で公開しない。抽象化しても匿名性は自動的に保証されない。公開用には、許可された範囲で個別に確認した新しい資産を作る。

現行seedはノード内全記録への同一アクセスを前提とする。詳細な権限ができるまでは別のノードディレクトリに分け、公開記録と私的記録の同一索引を作らない。索引の検索、グラフ伝播、件数表示の前に権限境界を適用する。

外部索引が大量の似た記録を送っても、それを支持や独立性の証明にしない。出典系列ごとの表示上限、予算、ローカル再計算を用意する。内容は実行命令ではなく参照データであり、記憶内の指示で権限を変えない。

## 12. 次のエージェントが実装する順序

1. [T010](../tasks/T010.md)の課題を担当宣言し、T007（索引／研究形式）、T002（MCP）、T004（画面）、T005（通信）と接続面を調整する。
2. 原本を変更しない抽出アダプター、提案プロファイルのvalidator、別索引、再構築を実装する。添付契約テストを出発点にする。
3. 話題・目的・操作・構造の候補生成と対応付け、原本取得を一つの検索として接続する。自由文抽出の費用と品質も測る。
4. BridgeとTransferAssessmentの保存・検索を実装し、実際に試した結果と類推候補を区別する。
5. 地図画面、型の抽出、連合検索を各担当と接続する。将来機能のために本命の表現力を削らない。

後段のUIやP2Pがなくても、CLI/MCPからエピソードと橋を調べられる最初の縦断実装は作れる。人手で綺麗に分類した数例だけに合わせるのではなく、雑多な記録から始めて欠落や抽出誤りを扱う。

## 13. 受入基準

添付の契約例はすべて架空であり、データ形式の整合性だけを試す。実世界の検索性能や有効な類推を証明するベンチではない。機能完成時には、原本から検索・対応付け・転用結果までを評価する。

- 原本CIDと署名を保持したまま取り込み、索引のみを削除して再構築できる。
- ノード名やJSON配列順を変えても構造特徴は同じになり、関係の向きや種類の変更は適切に反映される。
- 同じ話題だが探索経路の違う例と、異なる話題だが関係構造の近い例を区別して検索する。
- 同じ「行動→観測」型の無関係な記録を、役立つ類推として誤推薦する率を測る。
- 抽出されたノードと接続には原本位置があり、抽出器間の異なる解釈を併存させられる。
- Bridgeに試行結果を捏造せず、TransferAssessmentは実在する試行と出典を参照する。
- 反例、訂正、未実行、途中中断、観測不十分、参照不可を保持する。
- 同一系列の複製、言い換え、独立再実行を区別し、検索順位を真理の投票にしない。
- 私的記録を検索候補、関連数、キャッシュ、ログから漏らさない。
- 検索品質、転用の有用性、負の転用、取り込み費、検索p50/p95、RAM、生成呼出数を測る。手順と実測をPRに残す。

## 14. 先行研究との関係

以下は2026-09-17に一次資料の要旨・書誌を確認した。コード監査や追試は行っていない。本文のDSCC統合、方向付き特徴の仕様、対応付けと転用記録は本提案であり、各論文の成果をそのまま主張しない。

- [S4] Malkov & Yashunin (2016/2018), *Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs*. ベクトル候補探索。https://arxiv.org/abs/1603.09320
