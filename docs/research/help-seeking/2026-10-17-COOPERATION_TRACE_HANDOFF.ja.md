# R-HS研究更新（2026-10-17）— 自発的協力を「申告」ではなく「原本に戻れる履歴」から評価する

基準main: 90eb122087658dc2e5b9b1d553cd58877dd67620
研究分野: [R-HS](README.md) / [出典台帳](SOURCES_AND_EVIDENCE.ja.md) / [研究計画](RESEARCH_AGENDA.ja.md) / [Issue #28](https://github.com/AwakeningOS/DSCC/issues/28)

**状態:** 限定的なローカル実装と合成データの回帰テスト。実モデルの自発性、AIの学習、実人間との協働効果、外部通信の安全性は未検証。

## 1. 今回の判断

週次報告（2026-10-16）と一次資料を確認すると、次の順序で研究するのが妥当である。

1. **原本と行動をつなぐ。** 「困っている」「頼んだ」「回答が来た」という自己申告だけでなく、元の作業状況、実際に開示したと申告した情報、回答の原本、回答を採用した根拠を追跡可能にする。
2. **実モデルで状態復元を測る。** 依頼文だけを見た後任と、原本付きの履歴を見た後任を比較する。適切な依頼の文章が生成されたことと、支援者が問題を解けることは別。
3. **誰にいつ協力を求めるかを評価する。** 相談不要、相談有効、相手が混雑・拒否・誤回答する条件を混ぜ、総予算と人間の実作業負担を測る。
4. **求助能力の学習と創発を評価する。** 明示的な求助報酬、外部の固定規則、成果・費用中心の学習、未知の相手・課題への汎化を分離する。相談回数の増加だけで創発と呼ばない。
5. **権限・信頼の境界を別に守る。** 相談相手に見える文章や外部の推薦を、モデルや所有者への新しい命令にしない。公開可能な研究記録と機密情報を混ぜない。

これは「独立＝一切相談しない」という考えではない。**自分と他者の限界を踏まえて、任意の協力を自分から選べること**を研究する。

## 3. 実装範囲：ローカルの協力エピソード契約

新規の src/dscc/cooperation.py には、既存の ResearchService / AgentContribution のみを利用して、dscc.cooperation.step/0.1 のイベントを保存・読取するadapterを追加した。

イベントの共通フィールドは schema, episode_id, stage, initiator, previous_cid, evidence_cids, details。各ステージでdetailの必須フィールドを検証する。

- **assessment**: 不足、他の選択肢、実際の選択、根拠の申告。元の作業観測CIDを要求する。
- **request_draft**: 協力候補、候補を知った経路、依頼文、**開示を提案する**CID。記録しても送信しない。
- **dispatch_observation**: 外部で送信されたかという**申告**、経路、実際に開示したと報告されたCID。送信済みの申告には観測原本を必要とする。
- **response_observation**: 回答・部分回答・拒否・無回答・不明を別に記録。回答を観測したとの申告には原本CIDが必要。
- **verification**: 原本付きで、回答を支持・否定・判定保留したという記録。単なる回答受領とは別。
- **continuation**: 再開・保留・停止と次の作業。

段階の飛び越し、別プロジェクト／別エピソードを先行イベントに使うこと、相談を選んでいないのに依頼を作ること、送らなかった依頼への回答を記録すること、拒否された回答を検証済みとすることをadapterで拒否する。

事実性と認可は別。署名は署名者の鍵を示すだけで、本人の身元や回答内容の正しさを証明しない。initiator=agent_policy も自己申告であり、方策が自律的に意思決定した証拠ではない。

### 既存契約との整合

- 新しいseed kind、公開research type、MCP tool、権限、ネットワーク、通知、モデル実行は追加しない。
- T012の content.extensions は保持場所であり、協力adapter側が具体的な形・前段階・観測の根拠を検査する。参照する全CIDは同時にinput_cidsと署名付き親にも明示する。
- exportは祖先の原本を丸ごと含む。**CIDを引用することはその内容を他者へ見せても安全という意味ではない**。機密はそもそも共有可能なノードに入れない。現行のproject名は強いACLではない。
- 外部文書や返答に含まれる命令らしい文字列は**研究データとして保存するだけ**で、実行も送信もしない。
- 1 MiB／32親／256件8 MiBの既存境界を維持する。長期履歴の全体を無制限に閉包して渡す仕組みではない。

### 試験

新規 tests/test_cooperation.py は実モデルなしのfixtureで、履歴の整合、署名された原本へ戻れること、別ローカルノードへのbundled handoff、無相談・拒否・外部の偽推薦・不正な形式／親・履歴上限・連絡や実行権限が発生しないことを検証する。

必要なコマンド：

    python -m pytest -q tests/test_cooperation.py
    python -m pytest -q
    python -m dscc demo
    python scripts/check_repository.py

実測のCI結果はPRへ記載する。fixtureの成功はHS01/HS04/HS07/HS08/HS12の一部の「記録契約」が動く証拠であり、HS02/03/05/06/09/10/11の協働判断の品質・安全性試験を実施したことではない。

## 4. 次の実験順

**L2a: 状態復元。** 原ログのない後任モデルに依頼文のみ／原本CID付き／原本と説明付きの条件で引き継ぎ、読めたこと・参照したこと・作業が再開できたことを別々に測る。CTXGAP型の観測漏れを検査する。

**L2b: 協力相手の選択。** 同一課題で独力／検索／他AI／許可された人間の回答を比較する。相手の正答率・応答時間・混雑・拒否・費用を変え、事前に定めた品質と負担の双方を計測する。KL-PBDの数理をそのまま異種・不正確・拒否可能な専門家へ一般化しない。

**L2c: 信頼境界。** 公開ページの隠し文、回答内の権限偽装などを隔離fixtureで確認。**相談の受付と実行許可は別**。第三者への実際の自動連絡は許可・認証・同意が実装されるまで行わない。

**L3: 訓練・創発。** 明示的な求助学習、外部ルール、成果・費用中心の学習、別課題からの転用を同じ総予算・未知条件で評価。求助を学習できたことと、別目的の学習で副次的に獲得したことを厳格に区別する。

このPRでL2b/L2c/L3を実装した、実人間へ依頼した、創発を観測したとは主張しない。
