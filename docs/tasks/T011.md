## Current implemented base

The repository contains local large-block storage, versioned model/capability/training-run profiles, model inspection and a non-executing inference placement planner. It does **not** contain peer block transfer, GPU execution, model loading, distributed inference or training.

## First executable gate

Use a small, license-compatible open model on two explicitly trusted machines.

Acceptance:
- both machines verify the same signed model manifest and weight-block CIDs;
- runtime compatibility is checked before loading;
- one machine can stop and the failure is detected cleanly;
- model execution happens only through an owner-approved isolated runtime;
- output correctness and numerical differences are compared against a single-machine baseline;
- wall-clock, network bytes, memory and hardware/runtime versions are recorded;
- no result is described as public or permissionless until cross-NAT and adversarial tests actually pass.

## Training gate

Do not begin public volunteer pre-training by merely wiring gradients to arbitrary peers. First reproduce a low-communication method on trusted independent sites, then introduce churn, heterogeneity and malicious-worker tests one at a time while keeping the full intended design.

Ablations are derived from the strongest useful design; they are not reasons to permanently restrict the product architecture.

## 2026-10-09 implementation and research handoff

The local [planner correction](../PLANNER.md) in PR #24 recovers feasible capacity placements after greedy failure and reports bounded-search exhaustion as unknown feasibility. Successful legacy placements retain their plan IDs. Weight-block packing still does not establish a valid execution graph or per-device runtime memory sufficiency.

For lane E, read the [trusted-volunteer roadmap](../research/DSCC_2026_Distributed_AI_Architecture.md) and [October research update](../research/2026-10-09-RESEARCH_UPDATE.ja.md). Cross-Facility HPC pre-training is a candidate reference for mixed NVIDIA/AMD sites, data leases and departures; GeoMesh is a synchronous workload-balancing alternative, not an asynchronous method. Their reported results do not establish arbitrary consumer-GPU or hostile-network readiness.

Define the initial deployment's trust assumptions explicitly. Cooperative churn/rejoin/data-lease work need not wait for every permissionless defense in lane F. It must still preserve authenticated inputs, owner-authorized execution, withdrawal, checkpoint availability and clear fault reporting. Delayed completion, duplicate messages, state generations and the difference between processed data and accepted updates require explicit tests. Update this task's implemented status only from observed DSCC execution, not from a paper's existence.
