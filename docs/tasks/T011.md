# T011 — Distributed Open Model Commons execution

Status: **BLOCKED for public execution; READY for isolated planner/storage/runtime-interface work.**

Purpose: turn the local OMC foundation into real open-model distribution, heterogeneous inference and later volunteer low-communication training without weakening owner control or existing artifact provenance.

## Read first

Read `AGENTS.md`, `docs/STATUS.md`, `docs/PROTOCOL.md`, `docs/adr/0004-open-model-commons-foundation.md`, `docs/proposals/DISTRIBUTED_OPEN_MODEL_COMMONS.ja.md` and `docs/GLOBAL_SCALE_CHALLENGES.ja.md`.

## Current implemented base

The repository contains local large-block storage, versioned model/capability/training-run profiles, model inspection and a non-executing inference placement planner. It does **not** contain peer block transfer, GPU execution, model loading, distributed inference or training.

## First executable gate

Use a small, license-compatible open model on two explicitly trusted machines.

Acceptance:
- both machines verify the same signed model manifest and weight-block CIDs;
- runtime compatibility is checked before loading;
- one machine can stop and the failure is detected cleanly;
- model execution happens only through an owner-approved isolated runtime;
- output correctness and numerical differences are compared against a single-machine baseline;
- wall-clock, network bytes, memory and hardware/runtime versions are recorded;
- no result is described as public or permissionless until cross-NAT and adversarial tests actually pass.

## Training gate

Do not begin public volunteer pre-training by merely wiring gradients to arbitrary peers. First reproduce a low-communication method on trusted independent sites, then introduce churn, heterogeneity and malicious-worker tests one at a time while keeping the full intended design.

Ablations are derived from the strongest useful design; they are not reasons to permanently restrict the product architecture.
